# 路线提醒编排器（Route Alert Orchestrator）

把施工、班次、适行限制等提醒**标到具体线段**，由服务 API 计算**时空影响**，
关系库保存**路线几何（版本化）、规则与公告修订**。零外部依赖：Python 标准库 + SQLite + 原生 SVG/JS。

## 启动

```bash
cd route_alerts
python3 -m app.server 8080
# 打开 http://localhost:8080 （管理网页）
```

首次启动自动建库并装载演示数据（时间锚点 2026-10-07 周三）。

## 验收测试

```bash
python3 -m unittest tests.test_all -v   # 23 个用例
```

覆盖：跨日/跨夜施工、撤销公告迟到（双时间轴）、路线改线版本 diff、
旧离线计划重连重算、一条路段同时命中多项提醒、同名/包围框陷阱、
方向限行与班次窗口、老人/儿童/无障碍冲突解释、矛盾来源待核、
两规划策略对比、无解原因集合与关键割、确认版本绑定、打印新鲜度与缺信息。

## 模块

| 文件 | 职责 |
|---|---|
| `app/geometry.py` | 线段/折线/多边形精确求交（共线重叠、端点接触、穿入穿出）|
| `app/temporal.py` | 绝对生效窗口、周期班次（跨夜）、方向掩码 |
| `app/database.py` | 关系库 schema（路线/版本/成员、线段、公告、规则、命中、矛盾、确认、离线计划）|
| `app/seed.py` | 演示路网与 8 条公告（含矛盾对 ANN5/ANN6、同名陷阱 ANN8、迟到撤销 ANN4）|
| `app/engine.py` | 收录即求交、双时间轴可见性、规则适用、边状态、矛盾待核、路线评估 |
| `app/planner.py` | filter（先可达后筛选）与 prune（约束直接进入 A*）；无解原因集合+关键割 |
| `app/support.py` | 新鲜度/缺信息、已查看确认（版本绑定）、离线保存/重连、打印、改线发布 |
| `app/server.py` | HTTP API + 静态页（stdlib）|
| `web/` | 单页管理界面（SVG 地图：规则几何、线段、命中、待核高亮；节点手选）|

## 关键设计决策

### 1. 局部施工与路线“实际片段”求交
规则入库时立即与**全部物理线段做精确几何求交**，结果存 `rule_matches`。
- bbox 仅作快速预筛，不参与判定；
- 同名不命中：ANN8 标题含“南湖”，实际多边形只覆盖 S11 中段，
  同名的 R5（南湖支线，走 S15）**不被停用**；
- 包围框重合不命中：`geometry.py` 中 bbox 通过后仍逐边精确求交；
- 规则折线与线段仅在**共享节点点接触**（`contact_only=1`）时不据此封闭该路段；
  多边形穿入/穿出包围则中间区间在施工区内，算真实区间命中。

### 2. 方向与生效时段共同判断
- `direction`：B 双向 / F 仅数字化方向 / R 仅反向。ANN2 为“南行夜间抢修”，
  北行（反向）不适用——但 ANN3 的双向夜间封闭仍对北行生效。
- `windows`：绝对时间区间，天然支持跨多日（ANN1 10-05 22:00 → 10-08 06:00）。
- `weekly.cross_day`：跨夜班次/封闭，22:30 与次日 03:00 都命中，白天不命中。
- 渡轮/摆渡车/电梯的**运营班次**与规则分开给出 `OUTSIDE_SHIFT` 原因。

### 3. 两策略对比（先可达后筛选 vs 直接进入搜索）
- **filter**：纯拓扑 DFS 枚举全部简单路径，再逐边套人群/规则/班次。
  解释完整（每条被拒路径带原因），但会展开大量注定封闭的路径——演示中
  27 条候选、136 次边评估，13 条被筛掉。
- **prune**：A* 搜索时即时评估边状态，封闭即剪枝——同样问题 32 次边评估、
  展开 11 个节点；无解时由关键割诊断补齐原因集合。
- 无解诊断给出**原因集合**（不是单一报错），并标记**关键割**：
  单独放松该类约束（施工/管制/班次/人群）即可恢复连通。

### 4. 老人、儿童、无障碍的冲突解释
原因定位到**具体线段+依据公告**，绝不一刀切停用整条路线：
- 轮椅：`WHEELCHAIR_INACCESSIBLE`（S6 石阶固有属性 / S2 施工 / S13 电梯矛盾）；
- 老人：`ELDERLY_FORBIDDEN`（S6 健康限制），普通石板路不受影响；
- 儿童：S6 要求 ≥8 岁，6 岁 `AGE_TOO_LOW`，10 岁可过；其它线段不限。
同段同刻命中多项提醒时，原因并列展示（S5 在 23:30 同时命中 ANN2 抢修 + ANN3 夜封）。

### 5. 来源矛盾 → 待核，不拼接通行保证
同段同时存在生效的 block 与 allow（不同来源，如 ANN5 维保单位称停运、
ANN6 客服称正常）时，边状态为 `pending`，前端标“待核”，
规划中含待核边的方案 `guaranteed=false`，系统**不自行判断谁对**。

### 6. 公告修订与撤销：双时间轴
- `valid_at`（现实生效）/ `observed_at`（收录时间）分开保存；
- **撤文迟到**：ANN4 08:00 撤销、09:30 才收录——09:00 的查询者仍看到管制，
  10:00 的查询者看到 S7 恢复；撤销**不回改历史**，回看 10-06 规则依然在；
- 公告修订生成新规则版本，旧版置 `superseded`。

### 7. 路线改线
路线几何按 `(route_id, version)` 版本化；v2/v3 为全新成员边集合。
R1 v1 经 S2（崖电梯，施工封闭），v2 改走东湖连廊。离线重连检测
`reroutes`（R1 v1→v2）并以**当前数据重算**，明确警告旧计划不得继续作为通行保证。

### 8. 已查看确认只对应当时版本
`acknowledgements` 绑定 `(user, rule_id, rule_version)`；规则出新版后
`has_new_version=true`——打开过旧提醒**不会隐藏新变化**。

### 9. 网页呈现与打印
- 影响结果逐段给出**位置（线段/区间）、时间（时刻+班次窗口）、依据（来源+公告号）**；
- 定位被拒时可在 SVG 地图上**手选起终点**节点；
- 打印件含**新鲜度**（按来源 SLA：市级 24h / 运营方 12h / 景区 6h）
  与**缺信息范围**（规则缺时段、几何不命中任何线段、运营线段缺班次），
  并声明“结论仅覆盖已公告命中的线段，未公告区域不构成通行保证”。

## 主要 API

| 方法/路径 | 说明 |
|---|---|
| GET `/api/state` | 节点/线段/路线版本/规则（含命中）/公告/数据版本 |
| POST `/api/announce` | 录入或修订公告（入库即求交，返回命中线段）|
| POST `/api/revoke` | 撤销（`revoked_at` + `observed_at` 双时间）|
| POST `/api/reroute` | 发布路线新版本 |
| GET `/api/impact?route_id&version&at&observed_at&wheelchair&elderly&child_age` | 路线逐段时空影响 |
| GET `/api/plan?start&goal&at&mode=filter\|prune` | 两策略规划 + 无解原因集合 |
| POST `/api/ack` / GET `/api/ack` | 查看确认（版本绑定）|
| POST `/api/offline` / `/api/reconnect` | 离线保存 / 重连比对+重算 |
| GET `/api/print?format=text` | 打印件（新鲜度+缺信息）|
| GET `/api/freshness` `/api/missing` | 新鲜度 / 缺信息 |
| POST `/api/reset` | 重置演示数据 |
